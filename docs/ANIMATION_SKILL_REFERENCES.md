# Animation references and the YAAS renderer

This audit inspected the actual GitHub trees, skill files, implementation files and licenses below on 8 November 2026. These repositories are references for a bounded renderer. Installing a Markdown skill does not give the running YAAS Python application a new drawing engine, model, footage license or production-quality guarantee.

## What is deliberately not installed or adopted

Herk's kit includes editing workflows, draft cards and footage helpers. Some optional services consume API credits. Its example cards and brand material are not a source of factual claims or a ready-made YAAS scene planner. Its style-specific pacing and talking-head proportions are not universal rules for a calm ASMR channel or a news explainer.

The community repository contains independent skills with different prerequisites. Its camera-caption workflow is for particular talking-head shots and includes matte/model preparation; it is not a universal cinematic scene engine. Some examples pin a different HyperFrames version or use remote GSAP/font URLs. YAAS keeps its locally installed HyperFrames **0.9.19**, GSAP **3.15.1** and Inter assets, rather than changing those dependencies to match an example.

Artem's four quick JSON-driven skills have fixed geometry behind their small specifications. A phone breakdown does not become an accurate breakdown of a different machine by changing its labels. Its default map is illustrative, not a geographic data source. Its full 2D/3D engines expect an agent to write shot code and may install local voice/alignment models. One example explicitly needs care to remain seek-safe. YAAS does not run generated JavaScript, invent map locations or numeric chart values, replace the measured voice clock, install a second voice stack, or execute an external installer.

## Runtime contract and review criteria

New supported graphics scenes use `graphics_version: 2`. The saved `staging` object contains a version, allowlisted world, action and camera. Items have a symbol and one of `subject`, `support`, or `context`; there is exactly one subject and at most four items. The whole-film creative brief preserves theme, premise, continuity and a bounded palette. A selected scene can override its palette without rewriting other scenes. These are data choices interpreted by local templates, not model-generated executable code. Legacy v1 plans continue through their original renderer branch.

The new design should be evaluated with these concrete questions:

1. **Subject and mechanism:** Can a viewer identify what is acting and what changes, with sound muted? A generic water icon does not demonstrate a settlement adapting to rising water.
2. **Grounding:** Is every depicted actor or mechanism supported by that scene's narration? A broad reference to adaptation does not authorize an invented dam, floating house, statistic or country map.
3. **Spatial composition:** Does the subject occupy a useful share of the phone-size frame? Do supporting objects have a visible relationship? Are labels attached, readable and inside the frame throughout camera movement?
4. **Progression:** Do early, action and result frames show a change in the mechanism, rather than only a moving decoration or a replacement heading? Longer explanatory holds can be intentional; a global minimum-motion metric is not a substitute for this review.
5. **Timing and reproducibility:** Do the action cues use the saved narration clock? Does seeking backward and forward reproduce actor poses, labels, palette and camera without extending the video duration?
6. **Artifact integrity:** Does the decoded MP4 contain the same intended scene progression? Check actual encoded frames in both orientations, in addition to media structure, duration and frame-count verification.

The pinned local HyperFrames explainer, motion and review references reinforce these same constraints: explanatory objects rather than bullet slides, registered paused timelines, local assets and contiguous frame inspection.
